# 프로젝트 명세 관리 규칙

`doc/specs/`는 구현과 QA가 보장해야 하는 현재 동작의 기준이다. 프로젝트 작업 문서의 단일 기준 루트는 `doc/`다.

## 작업 절차

1. 구현 전 관련 명세를 읽고 요구사항·식별자·책임 경계를 확인한다.
2. 구현과 테스트를 함께 변경한다.
3. 동작, 데이터 계약, 공개 API 또는 시스템 책임이 달라지면 같은 작업에서 관련 명세를 갱신한다.
4. 기존 문서가 없는 신규 기능·시스템은 `snake_case_spec.md`를 추가한다.
5. QA 후 코드·테스트·명세가 일치하는지 확인한 뒤 CI 병합을 요청한다.

## 문서 작성 기준

- 실제 구현과 검증 가능한 계약만 기록한다.
- 데이터 참조는 정수 `idx` 흐름을 명시한다.
- 리소스 로딩 주체, 풀링 수명주기, 저프레임·오염 데이터 실패 동작을 명시한다.
- 관련 구현 파일과 테스트 파일을 연결한다.
- 일시적인 테스트 통과 개수나 커밋 해시는 명세에 고정하지 않는다.
- 단순 버그 수정처럼 외부 동작과 계약이 변하지 않으면 새 문서를 만들지 않는다.
