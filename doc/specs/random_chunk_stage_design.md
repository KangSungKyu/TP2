# 무작위 청크 스테이지 기획서

## 1. 목표

- 수작업 청크를 무작위 배열과 연결 그래프로 조립한다.
- 플레이어는 보스 직행, 안전 성장, 고위험 파밍 중 원하는 경로를 선택한다.
- Start와 Boss Gate만 필수이며 특정 전투·보상 청크 클리어를 강제하지 않는다.
- 스테이지 승리 시 다음 `StageData.idx`로 진행한다.

## 2. 런 구조

```text
HubScene
→ Stage Entry
→ N×M 청크 그래프 자유 탐색
→ Boss Gate
→ Boss Room
├─ 승리: 다음 Stage Entry
└─ 사망: HubScene
```

| 항목 | 기준 |
|---|---:|
| 배열 크기 | `1≤N≤6`, `1≤M≤6` |
| 일반 권장 크기 | `3×4–5×5` |
| 활성 청크 | `10–18개` |
| 동시 로드 청크 | 최대 `4개` |
| 보스 룸 | 배열 외부 별도 로드 |
| Start–Boss 최단 경로 | `2–4개` 연결 |
| 선택 분기 | 최소 `3개` |
| 순환 연결 | 최소 `2개` |

`1×1–2×2`는 튜토리얼과 생성 실패 Fallback에만 사용한다. `6×6`에서도 모든 셀을 채우지 않고 활성 청크를 최대 18개로 제한한다.

## 3. 플레이 방식

| 방식 | 방문 청크 | 특징 |
|---|---:|---|
| 보스 직행 | `2–4개` | 낮은 성장, 짧은 런, 높은 숙련 요구 |
| 균형 탐색 | `6–9개` | 표준 성장과 회복 |
| 고위험 파밍 | `10–14개` | Elite·희귀 보상, 높은 사망 위험 |
| 완전 탐색 | 최대 `18개` | 많은 선택권, 시간 비용과 체감 보상 감소 |

Boss Gate는 방문 수, 전투 클리어 수, 빌드 점수와 무관하게 입장할 수 있다. UI는 입장을 막지 않고 현재 빌드 기준 예상 위험도만 표시한다.

## 4. 청크 유형

| 값 | 유형 | 역할 |
|---:|---|---|
| `1` | Start | 시작, 빌드 확인, 지도 진입 |
| `2` | Combat | 일반 전투와 일반 보상 |
| `3` | Elite | 고위험 전투와 희귀 보상 |
| `4` | Reward | `3개 중 1개` 성장 선택 |
| `5` | Rest | 1회 회복·정비 |
| `6` | Event | 교환·변형·영구 해금 |
| `7` | Shop | 재화 기반 빌드 보완 |
| `8` | Challenge | 조건부 전투와 고등급 보상 |
| `9` | Shortcut | 탐색 시간 단축 |
| `10` | Treasure | 막다른 길 보상 |
| `11` | Boss Gate | 보스 정보 확인과 입장 |

## 5. 경로 생성 원칙

1. 외곽 셀 하나를 Start로 지정한다.
2. Start에서 거리 `2–4`인 셀을 Boss Gate로 지정한다.
3. Start와 Boss Gate 사이에 직행 경로를 만든다.
4. 직행 경로에서 성장·안전·고위험 경로를 분기한다.
5. 분기는 `2–4개` 청크 뒤 기존 경로와 합류하거나 보상 막다른 길로 끝난다.
6. 보상 없는 막다른 길은 허용하지 않는다.
7. 한 청크의 출구는 최대 `3개`로 제한한다.
8. 모든 활성 청크는 Start에서 접근 가능해야 한다.

## 6. 청크 구성 비율

| 유형 | 최소 | 최대 | 권장 비율 |
|---|---:|---:|---:|
| Start | `1` | `1` | 고정 |
| Combat | `4` | `9` | `45–55%` |
| Elite | `0` | `2` | `5–10%` |
| Reward | `1` | `2` | `10–15%` |
| Rest | `1` | `2` | `5–10%` |
| Event | `1` | `2` | `5–10%` |
| Shop | `0` | `1` | 최대 `5%` |
| Challenge | `0` | `1` | 최대 `5%` |
| Shortcut | `0` | `2` | `5–10%` |
| Boss Gate | `1` | `1` | 고정 |

## 7. Stage 1 기준

| 데이터 | 현행 값 |
|---|---:|
| `StageData.idx` | `9001` |
| Entry `ResourceData.idx` | `1040` |
| 기존 Battle `ResourceData.idx` | `1041` |
| Boss Room `ResourceData.idx` | `1042` |
| 보스 `UnitBaseData.idx` | `3201` |

신규 청크는 `ResourceData.idx 1050–1099`를 Stage 1 예약 범위로 사용한다. 실제 등록 전에는 미존재 데이터이며 문자열 키를 대체값으로 사용하지 않는다.

### 몬스터 풀

| `UnitBaseData.idx` | 역할 | 위협 비용 |
|---:|---|---:|
| `3101` | 패링 학습형 | `1` |
| `3102` | 회피·추적형 | `2` |
| `3103` | 가드·점프형 | `3` |
| `3201` | 철위병 가론, Boss 전용 | - |

### 전투 위협 예산

| Boss Gate까지 최단 거리 기준 진행도 | 일반 Combat | Elite |
|---|---:|---:|
| `0–25%` | `2–3` | 배치 금지 |
| `26–50%` | `3–4` | `5–6` |
| `51–75%` | `4–5` | `6–7` |
| `76–100%` | `5–6` | `7–8` |

- 활성 일반 몬스터는 최대 `4`마리다.
- 동시 공격 권한은 최대 `2`개체에만 부여한다.
- `3103` 두 개체의 동시 활성은 금지한다.
- 동일 몬스터 조합은 한 스테이지에서 최대 `2회` 사용한다.

## 8. 성장과 보상

| 획득 요소 | 내부 `BuildPower` |
|---|---:|
| 일반 축복 | `+1` |
| 강화 축복 | `+2` |
| 희귀 축복 | `+3` |
| 무기 강화 | `+2` |
| 최대 HP 강화 | `+1` |

`BuildPower`는 입장 조건이 아니라 위험도 안내와 밸런스 분석에만 사용한다.

| `BuildPower` | 보스 예상 난이도 |
|---:|---|
| `0–2` | 매우 높음 |
| `3–5` | 높음 |
| `6–8` | 표준 |
| `9–11` | 낮음 |
| `12 이상` | 과성장 구간 |

### 반복 파밍 제한

| 해당 Stage 보상 획득 횟수 | 재화·수치 보상 효율 |
|---:|---:|
| `1–4회` | `100%` |
| `5–7회` | `75%` |
| `8회 이상` | `50%` |

희귀 보상의 등급과 영구 해금은 체감 감소 대상에서 제외한다.

## 9. 보스 승리와 스테이지 진행

1. 보스 사망을 확정하고 중복 완료 처리를 잠근다.
2. 런 보상과 영구 해금을 지급한다.
3. 현재 `StageData.idx` 완료 상태를 기록한다.
4. `nextstageidx`를 검증한다.
5. 다음 스테이지용 시드를 발급한다.
6. 다음 Stage Entry를 로드한다.
7. `nextstageidx`가 없으면 런 완료 후 HubScene으로 복귀한다.

## 10. 기획 승인 기준

- 보스 직행과 성장 탐색이 모두 정상 전략이어야 한다.
- 평균 방문 청크는 활성 청크의 `40–70%`를 목표로 한다.
- 보상 없는 막다른 길이 없어야 한다.
- 특정 대응 메카닉이나 전투 청크를 강제하지 않아야 한다.
- 직행 보상은 기록·외형·해금 가속 중심으로 구성하고 성장 경로를 대체하지 않아야 한다.
- 생성 실패가 런 중단이나 저장 손상으로 이어지지 않아야 한다.

### 🧠 [GameDesigner 자율 회고]
- 기획 무결성 비판: 현재 일반 몬스터 3종만으로 10개 이상의 활성 전투 청크를 충분히 차별화하기 어렵고, 보상 체감 감소 수치는 실제 평균 방문율 검증이 필요하다.
- 차기 방어 지침: 표준 배열 적용 전에 일반 몬스터를 최소 6종으로 확장하고, 텔레메트리에서 평균 방문율 `40–70%`와 경로별 선택률을 확인해 보상 효율을 조정한다.
